## ノート PC のセットアップ

```bash
git clone https://github.com/rsasaki0109/vla_ros2.git   # 既にあれば git pull
cd vla_ros2

# 1) コア + 開発ツール (CI と同じチェック)
python3 -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
ruff check src tests ros2 && mypy src/vla_ros2 && pytest

# 2) プランナー / VLM を動かす環境 (transformers が [openvla] と衝突するので別 venv)
python3 -m venv .venv-vlm && . .venv-vlm/bin/activate
pip install --index-url https://download.pytorch.org/whl/cpu torch torchvision   # GPU なら通常の torch
pip install -e ".[vlm,dev]"

# 3) ROS2 Jazzy (必要なら)
./scripts/bootstrap_ros2_workspace.sh                       # msgs + vla_ros2
VLA_ROS2_PROFILE=gz ./scripts/bootstrap_ros2_workspace.sh   # + Gazebo
source install/setup.bash && export PYTHONPATH="$PWD/src:$PYTHONPATH"
```

- モデルは初回実行時に Hugging Face から落ちる: Qwen2.5-0.5B/1.5B/3B-Instruct
  (約 1 / 3 / 6 GB)、SmolVLM2、`lerobot/smolvla_base`。
- 手元 mypy では `cli/main.py` に untyped-decorator が 3 件出る (main でも同じ、CI は通る)。
- `ruff format --check` は既存ファイル 10 個で差分が出るが CI では見ていない。触ったファイルだけ整形する。

## 運用ルール・ハマりどころ

- Git: コミットは本人名義 (`Ryohei Sasaki <rsasaki0109@gmail.com>`)、Co-Authored-By なし、
  PR 本文に AI の署名なし (PLAN.md §10)。
- CI: `ci.yml` (test 3.10〜3.12 + ros2-smoke) と `gazebo-pr.yml` (`ros2/`, `src/vla_ros2/sim|runtime/`,
  `scripts/gz_smoke_*` を触る PR だけ)。Gazebo nightly は 2026-09-14 から無効で、手動実行は 403。
  ROS を使うジョブは `ubuntu-24.04` 固定 (`ubuntu-latest` が 26.04 になり Jazzy が入らなくなったため)。
- launch_ros は文字列引数を YAML として解釈する (JSON 文字列が壊れる)。`ParameterValue(..., value_type=str)` を使う
  (`task_pipeline.launch.py` の `text()`)。
- Gazebo を複数回起動するときは `GZ_PARTITION` を分ける (`gz_smoke_validate.sh` が自動で設定)。
- 非同期チャンク: chunk 長 < 2 × 推論遅延 (tick) だとレートが落ちる。ノードが警告を出す。
- プランナー評価中に `src/vla_ros2/planner.py` を編集しない。モデルごとに別プロセスで import し直すので、
  途中から別のコードで測ることになる (実際に一度これで 3B の結果を取り直した)。
- 小さい LLM は JSON 配列の閉じ `]` を出さずに止まることがある。`_first_json` が補っている。
